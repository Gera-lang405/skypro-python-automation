ОТЧЁТ О ДЕФЕКТАХ: класс StringUtils (string_utils.py)

Окружение: Python 3, pytest; тесты в файле test_string_utils.py
Итог прогона: 47 тестов прошли, 2 упали — оба из-за дефекта №1.


ДЕФЕКТ №1. Метод capitalize меняет регистр всех букв, кроме первой

Серьёзность: средняя (Major) — искажаются пользовательские данные
Приоритет: высокий — нарушена основная функция метода

Шаги воспроизведения:
1. Создать объект: utils = StringUtils()
2. Вызвать utils.capitalize("skyPro")
3. Вызвать utils.capitalize("hello World")

Ожидаемый результат (по документации метода: «делает первую букву
заглавной и возвращает этот же текст»):
- "SkyPro"
- "Hello World"

Фактический результат:
- "Skypro"
- "Hello world"

Причина: метод вызывает встроенный str.capitalize(), который не только
поднимает первую букву, но и переводит все остальные буквы в нижний
регистр. Названия, аббревиатуры и имена собственные внутри текста
портятся.

Как исправить (предложение для разработчика):
    return string[:1].upper() + string[1:]

Тесты, которые падают:
- test_capitalize_keeps_other_letters[skyPro-SkyPro]
- test_capitalize_keeps_other_letters[hello World-Hello World]


ДЕФЕКТ №2. Методы не проверяют тип входных данных

Серьёзность: низкая (Minor)
Приоритет: низкий

Шаги воспроизведения:
1. utils = StringUtils()
2. Вызвать utils.capitalize(None)

Ожидаемый результат: понятная ошибка о неверном типе данных,
например TypeError("Ожидается строка").

Фактический результат: AttributeError: 'NoneType' object has no
attribute 'capitalize'. Сообщение раскрывает внутреннее устройство
метода и не объясняет, что передан неверный тип. То же поведение у
trim, contains и delete_symbol.


ЗАМЕЧАНИЕ (требуется уточнение требований)

contains("SkyPro", "") возвращает True: пустая строка считается
«найденным символом». В документации не сказано, как должен вести себя
метод для пустого символа. Предлагаю уточнить у аналитика и добавить
это в документацию метода.
